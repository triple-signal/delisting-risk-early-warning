## 5. 신호 ② 공시 텍스트 `[보고서]`

- 사업보고서의 위험요인·계속기업 관련 문단을 연도별로 추출
- 문장 임베딩의 의미 유사도로 연도별 변화량 측정, 위험 서술의 삭제·축소를 신호로 사용
- 감사의견(적정/한정/부적정/의견거절)을 언어모형으로 분류·정형화

**세부 방법** `[결정 2026-11-10]` (구현: `src/audit.py`)

| 변수 | 정의 | 자료 | 상태 |
|---|---|---|---|
| T1 계속기업 불확실성 | 감사보고서 강조사항에 "계속기업"과 "불확실성"이 모두 있으면 1 | DART 감사의견 API 강조사항 | 구현 |
| T2 강조사항 유형 | 상폐절차(거래정지·실질심사·개선기간 등) / 소송·우발부채 / 특수관계자 | 같은 자료 | 규칙 기반 구현 `[구현]`, 언어모형 분류로 교체 예정 |
| T3 서술 변화량 | 1 − 올해·작년 MD&A의 코사인 유사도 (Brown·Tucker 2011; Cohen·Malloy·Nguyen 2020) | 사업보고서 원문 IV장 | 구현 (`src/disclosure.py`) |
| T4 위험 서술 축소 | 작년 MD&A 문장 중 올해 유사 문장이 없는 비율, 분량 증감률(로그) | 같은 자료 | 구현 |
| T5 제재·소송·사고 | 불성실공시 언급 수, 벌점 합계, 소송 사건번호 수, 소송·횡령배임 기재 여부, 상폐 절차 기재 여부 | 사업보고서 원문 XI장 | 구현 |
| MD&A 생략 | 작성기준에 따라 MD&A 기재를 생략했으면 1 (이때 T3·T4는 결측) | 사업보고서 원문 IV장 | 구현 |

- 감사의견 자체는 API에 이미 범주로 정형화되어 있으므로, 언어모형은 **강조사항 원문 분류**에 쓴다
- 임베딩: 한국어 지원 공개 다국어 모델(BGE-M3 또는 multilingual-E5)을 주로, 단순 유사도를 비교 기준으로. `[구현]` 현재는 비교 기준(글자 2~3개 조각 빈도의 코사인 유사도)만 구현, 형태소 분석기 없이 동작
- **문단 범위** `[결정 2026-11-10]`: 국내 사업보고서에는 10-K Item 1A 같은 표준 위험요인 장이 없음을 샘플로 확인
  - T3·T4는 **IV. 이사의 경영진단 및 분석의견**(MD&A). 모든 회사에 거의 같은 "예측정보에 대한 주의사항" 문단은 제외
  - T5는 **XI. 그 밖에 투자자 보호를 위하여 필요한 사항** 전체 (우발부채·제재·작성기준일 이후 사항). 유사도가 아니라 사실 항목을 추출
  - 제외: II-5 위험관리 및 파생거래(재무제표 주석과 같은 상투적 문구), V-1 외부감사(감사의견 API와 중복)
- `[구현]` 세부: 작년 문장의 올해 최대 유사도 0.5 미만이면 삭제된 서술. 15자 미만 조각은 문장에서 제외. 소송·횡령배임은 언급 뒤 30자 안에 '없'이 없을 때만 기재로 봄. 2020년 이전 보고서는 XI장 하위 항목에 제목이 없어 XI장 전체를 대상으로 함. 헤더와 실제 인코딩이 다른 파일(UTF-8 표기, 실제 EUC-KR)이 있어 둘 다 시도
- **파일럿 확인 (2026-11-10, 16개 기업 32개 보고서)**
  - 32개 모두 IV장·XI장 추출 성공. MD&A 생략 1개 기업(2개 연도)
  - T5는 사건군과 대조군 차이가 뚜렷함 (평균: 불성실공시 언급 0.62 vs 0.19, 소송 기재 0.50 vs 0.25, 상폐 절차 기재 0.44 vs 0.12). 사건 기업 1곳은 XI장에 횡령 사고 기재
  - 대조군 1곳은 과거 감리 결과로 거래정지·실질심사를 겪고도 상장을 유지 → 오경보(1종 오류) 사례로 보고 가능
  - T3·T4는 이 표본에서 차이가 거의 없음 (서술 변화 0.11 vs 0.12). 전체 표본과 임베딩 방식으로 다시 확인 필요

## 6. 신호 ③ 감사 정보 `[보고서]`

- 감사인 교체 여부
- 감사시간·감사보수의 급격한 변화

**세부 방법** `[결정 2026-11-10]` (구현: `src/audit.py`)

| 변수 | 정의 |
|---|---|
| A1 감사인 교체 | 당기 감사인 ≠ 전기 감사인 (0/1) |
| A2 감사시간 변화 | ln(당기 실제 감사시간 / 전기) |
| A3 비정상 감사시간 | 연도별로 ln(감사시간)을 ln(자산총계)·업종·연결 여부에 회귀한 잔차 (Simunic 1980 방식) |
| A4 감사보수 변화 / 비정상 감사보수 | A2·A3과 같은 방식 |
| A5 시간 초과율 | 실제 감사시간 / 계약 감사시간 − 1 |

- **"급격한 변화"를 % 기준으로 고정하지 않고 연속값으로 모형에 넣는다.** 파일럿에서 상폐 직전 기업의 감사시간·보수가 오히려 크게 늘어난 사례(+44%)가 있어 방향을 미리 정할 수 없음 (과소투입: Caramanis·Lennox 2008 / 고위험 기업 투입 증가: 위험기반 감사)
- 감사인 교체 사유(주기적 지정 vs 자유선임 교체 vs 재무기준 지정)는 가능하면 사업보고서 원문에서 구분. 미구현 시 교체 0/1만 쓰고 한계로 보고
- `[구현]` 자료 정리: 기간 구분은 기수(제N기) 숫자로 판단, 칸 안의 여러 숫자는 합산, 단위 없는 보수는 크기로 단위 추정(1만 미만 백만원, 1천만 미만 천원, 그 이상 원), 2019년 이전 서식(보수·총소요시간)은 대체 열로 사용
- 알려진 자료 문제: 감사시간 입력 오류 사례(146,799시간 등)는 고칠 수 없어 극단값 처리로 대응

## 7. 융합과 평가 `[보고서]`

- 세 신호를 표준화한 뒤 해석 가능한 방법(가중합 또는 로지스틱 회귀 등)으로 종합 위험점수 산출
- 기업별로 어느 신호가 얼마나 기여했는지 제시 (블랙박스 지양)
- 평가지표: AUC, 정밀도, 재현율, F1
- 모든 신호는 사건 발생 이전 시점 기준으로 정렬 (미래 정보 누출 방지)

**표준화 규칙** `[결정 2026-11-10]` (구현: `src/standardize.py`)

1. 방향 통일: 클수록 위험하도록. 방향이 불분명한 감사시간·보수 변수는 그대로
2. 감사시간·보수는 규모·업종 효과를 회귀 잔차로 제거 (6절 A3)
3. 극단값 처리: 사업연도별 상하위 1% 윈저화 `[구현]` (M-Score 극단값 문제도 융합 입력에서는 이 규칙으로 처리)
4. 사업연도별 z점수 (2018 신외부감사법, 2019 표준감사시간제 등 제도 변화로 인한 연도 효과 제거)
5. 0/1 변수는 그대로, 결측은 0으로 채우고 결측 표시 열 추가

- `[구현]` 3·4단계 기준값은 **같은 사업연도 기업들의 값**으로 정한다. 라벨을 쓰지 않고 그해 공시가 끝나면 알 수 있는 정보이므로 미래 정보 누출이 아니다. 학습 기간으로 제한하는 것은 모형 계수와 경보 기준점이다

**융합 방법** `[결정 2026-11-10]` (구현: `src/fusion.py`)

- 주 모형: L2 규제 로지스틱 회귀, 사건 가중치 부여(class_weight=balanced). 기업별 기여도 = 계수 × 표준화값 (합 + 절편 = 위험점수 로그오즈)
- 비교 기준: 신호별 단일 모형, 표준화 값 동일가중 평균 (H1 검증)
- 강건성 확인: 그래디언트 부스팅 + 순열 중요도
- 변수 수는 10개 안팎 (사건 156건, 변수당 사건 약 10건 원칙)
- 평가: AUC, PR-AUC, 정밀도·재현율·F1
- 학습·검증은 시간 순서로 분할 (무작위 분할 금지). `[구현]` 경보 기준점은 학습 기간에서 F1이 최대인 점수
- `[미정]` 학습·검증 연도 구체 범위

## 8. 파일럿 `[보고서]`

- 대상: 상장폐지·제재가 확정된 기업 5~10개 + 비교용 정상기업 같은 수
- 절차: 사건 직전 2개 회계연도의 M-Score·발생액 산출
- 판정: M-Score 임계값 초과 또는 발생액 상위 → "사전 경보 성공"

`[미정]` "발생액 상위"의 기준(상위 몇 %). 정상기업 선정 방법은 아래 "대조군 매칭"에서 결정

**1차 테스트 (2026-11-09, `src/pilot.py`, `notebooks/03_pilot_mscore.ipynb`)** `[구현]` 팀 확인 필요
- 대상: 폐지일자 2021~2025년 사건 기업 중 사유별 무작위 추출(시드 42). 할당 감사의견 3 · 실질심사 3 · 부도·파산 1 · 보고서미제출 1
- 직전 2개 연도 재무제표가 DART에 모두 있는 기업만 채택. 보고서미제출 사유는 해당 연도 보고서가 없어 전부 탈락 → 7개 기업
- 대조군 없이 사건 기업만 계산 (매칭 방법 결정 후 추가)
- 발견된 문제
  - 7개 중 3개 기업은 t-1 사업보고서가 **폐지일 이후에 공시**됨 → 미래 정보 누출. 아래 2차 테스트에서 기준 변경
  - 당해 보고서의 "전기" 금액이 전년 보고서의 "당기" 금액과 다른 경우가 3건. 1건(에스제이케이 2020)은 DART가 전년 숫자를 그대로 반환한 원자료 오류로 보임. 나머지는 재작성 또는 연결/별도 전환 추정
  - 매출이 거의 0이 되면 DSRI·SGAI가 극단값(예: DSRI 206)이 되어 M-Score가 비정상적으로 커짐. 극단값 처리(절단·윈저화) `[미정]`
  - 매출총이익이 음수면 GMI가 음수가 되어 해석이 어려움
  - DEPI 중립값 대체가 14개 기업-연도 중 11개 (감가상각비 계정 미검출)
  - 발생액 정의가 TATA와 같은 식이라 보조 지표로서 따로 정보를 주지 않음

**"직전 2개 회계연도" 기준** `[결정 2026-11-09]`
- 폐지일 **이전에 공시된** 사업보고서 중 가장 최근 2개 사업연도 (공시일 = DART 접수번호 앞 8자리)
- `[구현]` 탐색 범위는 폐지 연도 직전 3개 사업연도, 2018 사업연도 이상. 2개를 못 채우면 표본에서 제외

**2차 테스트 (2026-11-09, 위 기준 적용)**
- 선정 결과 8개 기업 (감사의견 3 · 실질심사 3 · 부도·파산 1 · 보고서미제출 1). 기준이 바뀌어 1차의 광림·에스제이케이 대신 애닉·자안바이오가 뽑혔고, 보고서미제출 사유(골든센츄리)도 채워짐
- 8개 중 6개 기업에서 직전 2개 연도 중 한 번 이상 M-Score 경보 (대조군 없어 비교 불가)
- 남은 한계: DART가 정정보고서의 접수번호를 주는 경우 공시일이 최초 공시보다 늦게 잡힐 수 있음 (예: 애닉 2022 사업연도 공시일 2024-01-19)

**대조군 매칭** `[결정 2026-11-09]` (파일럿)
- 같은 시장(유가증권/코스닥) · 업종코드(DART 기업개황 `induty_code`, 한국표준산업분류) 앞 2자리(중분류) 같음
- 규모: 사건 기업 t-2 사업연도 자산총계와 가장 가까운 기업, 1:1 비복원
- 후보: 현재 유가증권·코스닥 상장 + KIND 폐지 목록(2018~2026)에 없음 + 사건 기업과 같은 2개 사업연도 사업보고서 있음
- `[구현]` 규모 차이는 자산총계 비율의 로그 절댓값 |ln(대조/사건)|으로 잼. 결산월이 같은 기업만 후보. 대조군은 폐지일 이전 공시 조건을 따로 걸지 않음(정정공시로 공시일이 늦게 잡히는 문제 때문)
- `[구현]` 대조군은 현재 상장 기업이므로 결과에 실명 대신 대조군 ID(C01~)만 표시 (9절). 실명 대응표는 `data/pilot_control_map.csv`(GitHub 미업로드)
- 업종코드는 수집 시점(2026-11-09) 기준 현재 값. 과거 업종 변경은 반영되지 않음

**대조군 비교 결과 (2026-11-09)**
- 기업 단위 경보 비율: 사건군 6/8(75%), 대조군 1/8(12.5%). M-Score 중앙값 사건군 −2.02, 대조군 −2.77
- 표본이 8쌍이라 통계적 검정 의미는 없음. 방향성 확인용
- 문제
  - 애닉(t-2 자산 15억 원)은 같은 업종에 비슷한 규모가 없어 대조군 자산이 6.6배. 규모 차이 허용 한도 `[미정]`
  - 골든센츄리 업종코드 64992(비금융 지주회사)는 금융 및 보험업(64~66)에 속함. 금융업 처리 방법 `[미정]` 적용 대상인지 확인 필요

**감사 신호 점검 (2026-11-10, `src/audit.py`)**
- 사건 기업 8개 중 6개는 비교한 2개 연도 안에 이미 비적정 의견 또는 거래정지·상폐 절차 강조사항이 있음 → "사유 발생 후" 표시 필요성 확인 (3절 사건 시점)
- 대조군 8개는 모두 적정 의견, 계속기업 불확실성 강조사항 없음
